# depviz — визуализатор графа зависимостей pip-пакетов

Практическая работа №2 по дисциплине «Конфигурационное управление»,
вариант 11.

## Общее описание

`depviz` — CLI-инструмент для построения и визуализации графа зависимостей
пакетов Python (pip). Готовые менеджеры пакетов и библиотеки для получения
зависимостей не используются.

Текущее состояние — **этап 3: основные операции**. Приложение читает
параметры из YAML-файла, строит полный граф зависимостей пакета
(с учётом транзитивных зависимостей) обходом в ширину без рекурсии,
исключает пакеты по подстроке, находит циклические зависимости и умеет
работать с тестовым репозиторием из файла.

## Получение зависимостей из PyPI

Для пакета запрашивается JSON-описание `<repository>/<package_name>/json`
(JSON API PyPI, например `https://pypi.org/pypi/requests/json`) стандартным
модулем `urllib`. Из поля `info.requires_dist` (строки `Requires-Dist`,
PEP 508) извлекаются зависимости:

- имя приводится к каноническому виду PEP 503 (`Charset_Normalizer` →
  `charset-normalizer`);
- сохраняется ограничение версии (`<4,>=2`) и маркер окружения
  (`python_version < "3.10"`);
- зависимости с маркером `extra == "..."` пропускаются — они нужны только
  для необязательных возможностей пакета и при обычной установке
  не загружаются;
- повторы убираются, результат сортируется по имени.

Используется последняя версия пакета в репозитории. Менеджеры пакетов
(pip) и библиотеки для разбора зависимостей не используются.

## Построение графа

- **BFS без рекурсии** (`graph.build_graph`): очередь `collections.deque`,
  от корневого пакета по уровням. Для каждого пакета зависимости
  запрашиваются ровно один раз.
- **Фильтрация**: пакеты, имя которых содержит `filter_substring`
  (без учёта регистра), не попадают в граф и не обходятся дальше —
  вместе с ними отпадают зависимости, достижимые только через них.
- **Циклы**: множество уже найденных пакетов не даёт обходу зациклиться.
  Сами циклы ищутся отдельно (`graph.find_cycles`) обходом в глубину
  на явном стеке, тоже без рекурсии, и выводятся списком.

### Тестовый репозиторий

При `test_mode: true` параметр `repository` — путь к текстовому файлу:

```
# комментарий
A: B C      пакет A зависит от B и C
B: D
C: D E
D:          пакет без зависимостей
```

Имена пакетов — большие латинские буквы. Пакет, упомянутый только как
зависимость, считается пакетом без зависимостей. Ошибки формата
(строчные буквы, нет `:`, повторное описание пакета, корневой пакет
не описан) выводятся с номером строки, код завершения 2.

Примеры репозиториев — `examples/repos/`, конфигурации к ним —
`examples/stage3/`.

## Коды завершения

| Код | Значение |
|-----|----------|
| 0 | успешно |
| 1 | ошибка конфигурации |
| 2 | ошибка репозитория: пакет не найден, сеть недоступна, неверный ответ, ошибка в файле тестового репозитория |

## Параметры конфигурации

Конфигурация задаётся в YAML-файле (по умолчанию `config.yaml`).

| Параметр           | Тип    | Обязательный | Описание |
|--------------------|--------|--------------|----------|
| `package_name`     | строка | да  | Имя анализируемого пакета (правила имён pip, PEP 508) |
| `repository`       | строка | да  | URL репозитория (`http(s)://...`) или путь к файлу тестового репозитория |
| `test_mode`        | bool   | да  | Режим работы с тестовым репозиторием: `true` — `repository` это путь к файлу, `false` — URL |
| `filter_substring` | строка | нет | Пакеты, имя которых содержит эту подстроку, исключаются из анализа (по умолчанию пустая строка) |

Пример (`config.yaml`):

```yaml
package_name: requests
repository: https://pypi.org/pypi
test_mode: false
filter_substring: ""
```

### Обработка ошибок

Все ошибки выводятся в stderr с префиксом `Ошибка конфигурации:`,
программа завершается с кодом 1. Проверяются:

- конфигурационный файл не найден или не читается;
- синтаксическая ошибка YAML, корень YAML — не словарь;
- не задан обязательный параметр или задан неизвестный;
- `package_name` пустой или не соответствует правилам имён pip;
- `repository` пустой; при `test_mode: false` — не URL `http(s)`;
  при `test_mode: true` — файл не существует;
- `test_mode` не логическое значение;
- `filter_substring` не строка.

Примеры некорректных конфигураций лежат в `examples/errors/`.

## Структура

```
src/depviz/config.py        загрузка и проверка конфигурации
src/depviz/requirements.py  разбор строк Requires-Dist (PEP 508)
src/depviz/pypi.py          загрузка описания пакета из репозитория
src/depviz/testrepo.py      чтение файла тестового репозитория
src/depviz/sources.py       выбор источника: PyPI или тестовый файл
src/depviz/graph.py         BFS-построение графа и поиск циклов
src/depviz/__main__.py      точка входа CLI
tests/                      модульные тесты (unittest)
examples/                   конфигурации и тестовые репозитории
run.sh, run.bat             скрипты запуска и тестов
```

## Сборка и запуск

Требуется Python 3.10+.

```bash
python -m pip install -r requirements.txt
```

Запуск (Linux/macOS — `./run.sh`, Windows — `.\run.bat`):

```bash
./run.sh                                  # config.yaml
./run.sh --config examples/stage3/cycle.yaml
```

Запуск тестов:

```bash
./run.sh test
```

## Примеры использования

Ромб без циклов (`examples/stage3/simple.yaml`):

```
Граф зависимостей пакета A
  тестовый репозиторий: examples/repos/simple.txt
  A -> B, C
  B -> D
  C -> D
  D -> (нет зависимостей)
Циклических зависимостей нет
```

Циклы, в том числе пакет, зависящий от себя
(`examples/stage3/self_cycle.yaml`):

```
Граф зависимостей пакета A
  тестовый репозиторий: examples/repos/self_cycle.txt
  A -> A, B
  B -> C
  C -> B
Циклические зависимости:
  A -> A
  B -> C -> B
```

Фильтр разрывает цикл (`examples/stage3/cycle_filter.yaml`):

```
Граф зависимостей пакета A
  тестовый репозиторий: examples/repos/cycle.txt
  фильтр: 'C' (исключены: C)
  A -> B
  B -> (нет зависимостей)
Циклических зависимостей нет
```

Реальный пакет с фильтром (`examples/stage3/flask_filter.yaml`):

```
Граф зависимостей пакета flask
  репозиторий: https://pypi.org/pypi
  фильтр: 'markup' (исключены: markupsafe)
  flask -> blinker, click, importlib-metadata, itsdangerous, jinja2, werkzeug
  blinker -> (нет зависимостей)
  click -> (нет зависимостей)
  importlib-metadata -> lazy-importer, zipp
  itsdangerous -> (нет зависимостей)
  jinja2 -> (нет зависимостей)
  werkzeug -> (нет зависимостей)
  lazy-importer -> (нет зависимостей)
  zipp -> (нет зависимостей)
Циклических зависимостей нет
```

Другие случаи: `large.yaml` (несколько уровней и два цикла),
`large_filter.yaml`, `from_middle.yaml` (корень в середине графа),
`root_filtered.yaml` (фильтр исключает сам корень),
`examples/errors/bad_test_repo.yaml`, `examples/errors/missing_root.yaml`.

## Демонстрация этапов

Каждый этап сохранён отдельным коммитом. Чтобы показать этап, переключитесь
на его коммит и запустите программу (Windows: `.\run.bat`,
Linux/macOS: `./run.sh`).

| Этап | Коммит    | Что показывает |
|------|-----------|----------------|
| 1    | `68c20a5` | вывод параметров конфигурации в формате `ключ=значение` |
| 2    | `325e03a` | вывод прямых зависимостей пакета с PyPI |
| 3    | `main`    | граф зависимостей (BFS), фильтр, циклы, тестовый репозиторий |

```bash
git checkout 68c20a5
.\run.bat
.\run.bat --config examples/test_mode.yaml
```

Вернуться к последней версии:

```bash
git checkout main
```

Сообщение Git о «detached HEAD» после `git checkout <коммит>` — это
нормально: просматривается старый коммит, ничего не теряется.
